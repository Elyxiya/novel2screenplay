# 分镜深化（规则增强，仅镜头层面）

## Summary

在 P0「小说→剧本→分镜」贯通已验收的基础上，对 ③ 分镜线的核心生成器 `dramatize` 做**纯规则增强**（不新增 LLM 依赖），把分镜从"机械拆块"提升到"能成片参考"的粒度。**仅触及镜头（Shot）层面**，不改 Drama 单层结构、不引入集/字幕稿分层、不做批处理/排序等非本期内容。

北极星：在不引入外部依赖的前提下，让每个镜头的景别、运镜、时长、情绪、氛围、环境音、字幕稿更贴合内容，产出确定性高、可测、可回溯。

## Current State Analysis

当前生成逻辑（[dramatize.ts](file:///e:/桌面/novel/novel2screenplay/apps/screenplay/src/lib/drama/dramatize.ts)）：
- **动作块**按固定 `ACTION_MAX_CHARS_PER_SHOT=100` 字符硬切分 → 常在句中被拦腰截断，镜头语义不完整。
- **对白镜头**：`shotType` 仅按场景角色数推断（1→close-up / 2→two-shot / n→medium），运镜恒为 `static`，无情绪/氛围/音效。
- **每个场景**：没有定场镜头（establishing shot），直接进入内容块。
- **运镜/景别**靠少数正则词命中（走|跑→track、看→dolly-in、转→pan），覆盖面窄。
- 时长仅按字数估算，无内容类型加成。
- 契约 [drama.ts](file:///e:/桌面/novel/novel2screenplay/packages/contracts/src/drama.ts) 的 `Shot` 无情绪(mood/emotion)、环境音(sound)、字幕(subtitle)字段，仅 `visual/action/notes`。

存在的可复用输入：[screenplay.ts](file:///e:/桌面/novel/novel2screenplay/packages/contracts/src/screenplay.ts) 每个场景含 `slugline`、`timeOfDay`、`locationId`、`summary`、`content`（action/dialogue 块带 `direction` 与 `sourceRefs`）；`Scene.localType`/`Location.description` 可推环境音。这些足以支撑纯规则增强。

## Proposed Changes

### 1. 契约增强（`packages/contracts/src/drama.ts`）
`ShotSchema` **仅新增可选字段**（`optional`，带默认/可缺省 → 既有存储的旧分镜 YAML 仍可解析，向后兼容，`formatVersion` 保持 `novel2drama-v1` 不变）：
- `mood: z.string().optional()` — 镜头情绪/氛围标签（如 `紧张`、`肃穆`、`清新`）。
- `sound: z.string().optional()` — 环境音/音效指示（如 `夜虫鸣`、`雨声`、`刀剑碰撞`）。
- `characterEmotion: z.string().optional()` — 说话人情绪（仅对白镜头，由语气/标点/方向词推出）。
- `subtitle: z.string().optional()` — 落屏字幕稿：对白镜头=台词 `line`；动作镜头=白描句。

不动既有字段（shotId/shotNumber/sceneNumber/slugline/shotType/cameraMove/durationSec/dialogue/speaker/visual/action/notes）。序列化（`serializeDramaToYaml`/`safeParseDramaFromYaml`）逻辑无需改，`DramaSchema` 透传新可选字段；**但需补一条回归测试**验证"旧分镜 YAML（无新字段）仍可往返解析"。

### 2. 生成器增强（`apps/screenplay/src/lib/drama/dramatize.ts`）
在 `dramatize` 内做如下纯规则改造（全部确定性、可单测）：

- **动作块按语义断句切分**：替换 `splitActionDescription` 的固定 100 字切法，改为按 `。！？…！？/\n` 及 `，`、`、` 处分句，优先在完整句/分句切，每镜更接近一个完整动作节拍；单镜仍设上限防止过长（保留 `ACTION_MAX_CHARS_PER_SHOT` 作为兜底合并上限）。
- **每个场景追加定场镜头**：场景内容非空时，在首块前插入一个 establishing shot——`shotType` 由 `location` 类型/`summary` 推（如 `wide`/`extreme-wide`）、`cameraMove` 多为 `static`/`pan`、`visual` 复用 `slugline + location.description + summary`、时长约 4–6s、`notes='定场镜头'`；空场景沿用现有兜底镜头逻辑不作重复。
- **景别/运镜细化**：
  - 对白：`characterEmotion` 由 `direction` + 台词标点（？！→激动，。…→沉吟）推出；`shotType` 在角色数为 1 时结合情绪给 `close-up`/`extreme-close-up`；保留 2→`two-shot`、n→`medium`。
  - 动作：`cameraMove` 扩展关键词映射（打斗/厮杀/挥舞→`handheld`，追逐/奔跑→`track`，切入/审视→`zoom-in`，环视/拉开→`pan`，其余 `static`）；`shotType` 按内容性质（激烈→`medium`/`full`，静景环境→`wide`，细节道具→`close-up`）。
  - `mood`：由 `timeOfDay`（夜→悬疑/静谧、清晨→清新、黄昏→苍凉、其余中性）+ 动作关键词（打/追→紧张、死亡/诀别/泪→悲怆）+ 对白 `direction`（哭→悲伤、笑→轻快）加权，取最显著者。
  - `sound`：由地点类型（外景+夜→虫鸣/风声；雨相关→雨声；打斗→刀剑碰撞/破风声）+ `timeOfDay` 兜底。
  - `subtitle`：对白=台词文本；动作=一句白描（首句或 `visual` 精简版）。
  - 对白镜头 `cameraMove` 保持 `static` 为主，但允许场景情绪强烈时个别用 `dolly-in`（焦点推进到说话人）。
- 保持溯源不变：`sceneNumber`、`metadata.sourceScreenplayId/sourceNovelId/sourceNovelTitle` 全部照旧。定场镜头也带 `sceneNumber`。

> 说明：引入定场镜头与字段派生会改变现有 `dramatize.test.ts` 的**镜头数量与字段断言**，属预期内的产物升级，需同步更新该测试文件的断言（见第 4 节）。

### 3. UI 呈现（`apps/screenplay/src/app/shortdrama/page.tsx`）
`ShotCard` 在每张镜头卡上，当对应可选字段存在时展示：
- 情绪/氛围徽标（`mood`）、环境音（`sound`，如 `#雨声`）、说话人情绪（`characterEmotion`）。
- 字幕稿行（`subtitle`，弱化样式）。若字段缺省则不渲染，不影响旧分镜展示。

不做：批量编辑/排序/序号重排/质量校验/统计面板增强（保持现有统计面板不动）。

### 4. 测试（`apps/screenplay/src/__tests__/`）
- **更新** `dramatize.test.ts`：适配新增定场镜头与字段，断言——每场景有定场镜头、动作切分在语义断点（单镜含完整句，无句中截断）、对白情绪/氛围/音效/字幕推导正确、时长/景别/运镜符合新规则。
- **新增** `dramatize-deepen.test.ts`：
  - 旧分镜 YAML（无 mood/sound/emotion/subtitle）经 `safeParseDramaFromYaml` 可往返解析（向后兼容）。
  - 新分镜 `serializeDramaToYaml`→`safeParseDramaFromYaml` 往返后新字段保留。
  - 定场镜头 `sceneNumber` 溯源正确；回溯字段完整。
- 目标：既有 259 用例除上述更新外全部保持绿。

## Assumptions & Decisions

- **路线**：纯规则，不引入 LLM；确定性可测。
- **粒度**：仅镜头（Shot）层面；不做集/字幕稿分层、不做成片导出。
- **兼容**：新增契约字段一律 `optional`，`formatVersion` 不变，旧分镜数据不迁移、可继续读。
- **测试改动**：接受对现有 `dramatize.test.ts` 镜头数/字段断言的必要更新（产物升级所致）。
- 新增可选字段具体名（`mood/sound/characterEmotion/subtitle`）与判定阈值以本方案为准，属实现细节可在实现时按最保守策略微调，但契约字段名与"全部 optional"这一决策不变。
