# 别名覆盖离线回放（P1/T2）

> 日期：2026-10-23。只读库、零 LLM 成本。工具：`scripts/eval/alias-replay.mjs`（直接导入产品代码 `alias-normalize.ts`，不复制规则）。
> 复现：
>
> ```bash
> node scripts/eval/alias-replay.mjs                 # baseline 10 次运行
> node scripts/eval/alias-replay.mjs --all --extended  # 全库 72 job + 扩规则反事实
> ```

## 口径

- 已登录角色：`phase1Output.characters` 的 `name ∪ aliases`。
- 未登记出场名：`phase2Output.scenes[].keyCharacterNames` 中不在已登录集合的标签。
- 规则：`resolveAliasCandidate(tag, characters)`，与线上同一函数。
- 分类：可合并（返回唯一候选）/ 无法匹配（null）/ 误合并风险（可合并但标签是描述词）。

## 结论

1. **baseline 指定的 10 次运行：未登记 0 种、0 次。** 10 个 job 全部走 auto→mapreduce，Phase1 reduce 已把出场名并进卡片的 `aliases`，别名规则在现行基线上不触发。这不是规则失效，而是上一轮「卡不全」问题被 Phase1 分流解决了。
2. **全库 72 个有 phase2 的 job（含 2026-10-21 truncate 期）：40 个存在未登记，46 种 / 546 次。**
   - 可合并：**3 种 / 19 次**（维克托、萧熏儿、摩根）。
   - 无法匹配：**43 种 / 527 次**；按标签聚合，前三位是 方晓语 170 次、胖妹 74 次、李方法 55 次——都是「卡里没有这个角色」，不是变体匹配问题。
   - 误合并风险：**0 种 / 0 次**（唯一候选 + 严格前缀/同长规则的直接结果）。
3. **扩规则收益为 0。** 反事实「剥掉 们/下属/头目/头子/父亲/……”等后缀再走现有规则」：多合并 **0 种 / 0 次**，反而新增 **1 处**误合并（海盗下属 → 海盗大副）。结论：不要再加匹配规则，杠杆在 Phase1 卡片覆盖。

> 账本第 376 行「10 次运行里未登记 23 种」是 2026-10-21 truncate 期、卡片较薄时的测量；当时的 10 个 jobId 未落库记录，无法逐条复现。本报告把可复现口径固定为「baseline 10」与「全库 72」，后续引用只从这里取数。

## 建议

1. **不扩匹配规则**：收益 0、且后缀规则已证明会误并群体词。
2. **保持唯一候选约束**，并把「别名重复登记」列入 Phase1 质检项（4 组已存在）。
3. 真正的覆盖缺口在「卡里没有角色」：43 种里绝大多数是旧 truncate 卡片缺人；auto→mapreduce 后 baseline 10 已归零。若要让历史数据可比，只能重跑，不能靠规则补。
