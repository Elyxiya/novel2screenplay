## 二、判定：不是「切分阈值」，是三层叠加

三章原文分别 2176 / 3822 / 3622 字，均未触发 Phase2 的 fallback 切分，场景边界全部来自 LLM 一次输出。因此账本里「属切分阈值问题」的表述不成立，实际是：

1. **提示词过切（主因）**：#2/#3/#5 都是原文单段的过场/反应/对话，模型把「换地点」「换时间」当成新场景，独立成场；#4 是内心句被孤立。#5 还把地点标错（宿舍 vs 食堂）。
2. **边界光晕放大（放大器）**：`Phase2Segmenter` 对 LLM 边界做前 −1 / 后 +2 段扩展，7/47/30/46/14 字的段落被扩成 111/118/136/71/87 字，看起来像「正常场景」，掩盖了它本来只有一句。
3. **合并规则按地点键控（兜底失效）**：`mergeAdjacentScenes` 只在同地点、同时间且合计 <800 字时合并；跨地点的过场永远不会被并回去，所以 #39→#40→#41 这种同一次外出被拆成三段。
4. **附带发现：重叠未真正截断**：`resolveOverlappingPerChapter` 注释写「truncate this scene to start from where previous ended」，代码只 `push({...scene})` 并更新 `currentEnd`，没有改 `start`。证据：246–364 与 285–421 重叠 79 字；1023–1094 同时压住 1088 与 1041。
5. doupo #1 单独一类：**章节标题被当成段落 0**。模型把范围给成 p0–0，边界扩展把正文 p1 吞进来，下一场又从偏移 0 开始，造成同段内容进两个场景。

## 三、最小修复方案（本批不实施）

| 方案 | 改动点 | 解决 | 风险/成本 |

| A 标题不入段 | `calculateCharOffsets` 跳过 `^第[一二三四五六七八九十百\d]+章` 行，段落 0 从正文起 | #1 | 全库段落编号整体 −1，金标注与历史基线需按新口径重跑；需预算 |
