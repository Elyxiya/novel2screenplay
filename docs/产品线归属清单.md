# 产品线归属清单（Architecture Ownership）

> 版本：v0.1.0 ｜ 编制日期：2026-08-25 ｜ 阶段 2：架构定型（① 归属清单）
> 前置：`产品定义.md §4`（三条产品线 MVP 边界）。本清单是「解耦分层、暂不拆」的静态基准：每条线的 routes / api / lib / 数据表归谁，共享底座边界在哪，以及待解耦的耦合点。

---

## 1. 依赖原则（一次性写死，lint 冻结）

- **竖向依赖**：三条产品线只准依赖「共享底座（L0）」与 `@novel/contracts`。
- **横向禁止**：①/②/③ 之间互不 import（lib 层由 `eslint-plugin-import` 的 `import/no-restricted-paths` 冻结，见 §4）。
- 例外：全链路业务编排（①→②→③ 的数据流转）在 **app/api 边界**完成（如 `drama/convert`），不落在 lib 互引上。

```
L2 产品线：① 灵感作家 · ② 小说改编 · ③ 短剧工坊   （互不 import）
              │                   │
              ▼                   ▼
L0 共享底座：auth · llm · agent 运行时 · sse · store(sqlite) · 基础 UI · debug
```

## 3. 共享底座（L0）

| 块 | lib / 前端 | 说明 |
|----|------------|------|
| 认证 | `lib/auth`、`app/auth/*`、`api/auth/*`、`components/AuthForm|AuthStatus|RequireAuth` | 会话 Cookie |
| LLM | `lib/llm/**`（Provider/Router/Registry/prompts） | DeepSeek/OpenAI/自定义 |
| Agent 运行时 | `lib/agent`、`lib/multi-agent`、`lib/agent-chat`、`lib/tools` | 多角色编排 |
| SSE | `lib/sse` | 实时推送 |
| 存储底座 | `lib/store/sqlite`（db/schema）+ `lib/store/job-store` | 多用户隔离 |
| 基础 UI | `components/ui/*`、`HeaderNav`、`ModelSelector`、`WorkflowStepper` | |
| 调试 | `lib/debug`、`app/debug`、`api/debug/*`、`api/health`、`api/models`、`api/cost-estimate` | |
| 数据表 | `users`、`sessions`、`schema_version`、`agent_tasks` + **共享资产表 `novels`** | |

> **共享资产表 `novels`**：被 ①（draft）与 ②（upload）同时写入，靠 `kind` 字段隔离——是两条产品线的数据接缝，非各自私有表。

## 4. 跨线边界与 lint

见 `apps/screenplay/eslint.config.mjs` 中的 `import/no-restricted-paths`：
`lib/drama/**`（③）↔ `lib/{pipeline,novel,jobs,result,eval}/**`（②）互不引用。
lint 通过为该边界生效基线；后续补抽 `@novel/*` 包后逐步收紧到包级使用规则。
