# ADR-0003：剧情压缩策略——可选档位化，保护集优先，决策全量可回溯

- 状态：**ADR 已定（设计批交付）**；最小可行档位 POC 待实施（本 ADR 第八节）
- 日期：2026-09-11
- 相关台账：D-24（压缩/分集缺席）、D-25（双向度量，配合裁决）
- 相关代码（未来落点）：`lib/pipeline/compression.ts`（新）、Phase2 后处理之后、`lib/drama/dramatize.ts`（分集）

## 一、背景：产物形态错配

现状策略是"忠实改编、不压缩"（不切支线、无目标集数、无节奏单元）。短剧形态是**分钟级结构 × 几十集**，
几十万字小说原样转出的剧本"像剧本但没法拍"——这是从"转换 demo"到"可交付初稿"之间最大的一道沟
（台账 D-24）。压缩不是可选优化，而是产物形态的必需件；但**强行压缩会与"忠实度"叙事冲突**，
因此本 ADR 的核心是：把"取舍"从隐含创作行为变成**显式、可选、可回溯的工程决策**。

## 二、决策

1. **档位化、默认 off**：压缩是一个显式 profile（`compression.profile`），默认 `off` 与现状零变化；
   只有用户显式选择档位才改变产物。
2. **保护集优先（确定性信号，非模型自由心证）**：以下内容**永不 DROP，降级须显式记录**：
   - `isMajor=true` 角色出场场景（Phase1 设定卡信号）；
   - open threads 的起点章与回收章（Phase1 卡信号，按章节区间查询）；
   - 死亡/揭示事件所在章（评估标注集 / 断言集信号，跨样本通用时用 identity 规则口径）。
3. **删减判据可解释、按规则编号落数据**：每个场景的处置必须携带 `reason(rule id)` 与 `protectedHits[]`；
   **禁止模型静默砍戏**（与 mergeProvenance 同源纪律：决策落数据才能被审计与回滚）。
4. **先做确定性 POC，LLM 语义压缩留待 v2**：v1 只做规则可解释的 MERGE/DROP/CONDENSE 标记；
   "这段真的水"的语义判断不做——不可解释的删减无法进评估链，也无法对用户交代。

## 三、判据与动作（v1 规则集）

| 动作 | 定义 | 判据（全部确定性） |
|---|---|---|
| KEEP | 原样保留 | 默认；命中保护集必为 KEEP（v1 无例外） |
| MERGE | 相邻场景合并为一 | 复用 Phase2 合并机制（同地点/同时段/双短），档位放宽阈值参数 |
| DROP | 整场景删除（唯一破坏性动作） | ①`keyCharacterNames` 全部 `isMajor=false` **且** ②不命中保护集 **且** ③档位允许（仅 `standard+`） |
| CONDENSE | 场景内压缩（景物/铺陈 → 一句动作摘要），场景保留 | v1 仅**标记**（决策表输出），执行留 v2（需要 Phase3 指令支持的证据） |

## 四、档位定义（profile 参数化，非离散魔数）

```ts
interface CompressionProfile {
  level: 'off' | 'light' | 'standard' | 'aggressive'; // 默认 off
  targetSceneRatio?: number;   // 目标场景数比例（light≈0.7 / standard≈0.5 / aggressive≈0.3）——初始建议值，POC 后校准
  mergeShortChars?: number;    // MERGE 短场景阈值（默认沿用 800，档位可放宽）
  allowDropMinor?: boolean;    // 仅 standard+ 为 true
}
```

**数字是初始建议值**：按"先测量后定阈"纪律，档位比率在首个 POC 人工评审后校准并回写本 ADR。

## 五、可回溯（硬要求）

压缩决策随产物落库：`pipelineState.compression = { profile, decisions: [{sceneIndex, action, ruleId, protectedHits, note?}], stats: {kept, merged, dropped, condensed, dropRatio} }`。
- DROP 决策必须能回答"删了什么、依据哪条规则、有没有碰到保护集"；
- 与 FIX-20（双向度量）联动：压缩后的**原文信息覆盖率**下降是预期内的，但必须**与编造率同报告**，
  防止"多删"伪装成"没编造"（D-25 的原始动机）。

## 六、分集（B-13）并入本家族

压缩与分集是**同一根轴（节奏单元）**的两端：压缩决定"总共有多少场景"，分集决定"它们如何入集"。
- 共享 profile：`episodeTargetMinutes`（每集目标时长）与 `hookPolicy`（集末钩子规则）；
- 分集执行在 drama 层：复用 `dramatize.ts` 的场景时长估算，按集预算切分/合并 + 集末悬念句检测（规则）；
- 顺序：FIX-19 档位（本 ADR）→ B-13 分集（同族实施）；分集视图属序列化扩展，随风格批（C6）一起进契约，
  不单开契约批。

## 七、与现有系统的接点（避免新造）

| 系统件 | 用法 |
|---|---|
| Phase1 设定卡 | 保护集信号源（isMajor / openThreads 区间） |
| Phase2 后处理 | 压缩决策层插在其后（新模块 `lib/pipeline/compression.ts`），复用其合并/边界数据结构 |
| identity 断言集 | 死亡/揭示章的保护信号；压缩后重跑断言作为回归 |
| drama 规则引擎 | B-13 分集时长估算复用其规则常量 |
| 评估链（FIX-20） | 压缩损失裁决（覆盖率 + 编造率双向报告） |

## 八、最小可行档位（POC）设计——本 ADR 的下一步

- **形态**：离线脚本 `scripts/eval/compress-preview.mjs`（**纯规则、零 LLM、零成本**）
  输入：既有 `pipeline_state`（phase1Output 卡 + phase2Output 边界 + phase4Output 产物）+ 样本 annotation；
  输出：①决策表 JSON（含每场景 action/ruleId/protectedHits）②人读压缩大纲 Markdown（场景序列 + 被删清单 + 保护集命中报表）。
- **跑法**：对 `zhanlan-short` 现有产物 + `profile=light` 与 `standard` 各出一份决策表。
- **验收**：人工评审"该保的保了、该删的删了"（评审记录入档）；据此校准档位比率（第四节）。
- **为何先跑 POC 再谈 LLM 压缩**：规则版全绿/可控后才能把语义压缩的增量说清楚；顺序反了就是用模型的不确定性
  掩盖判据的缺失。

## 八点五、POC 首跑观察（2026-09-11，校准输入，待人工评审）

对 `zhanlan-short`（mapreduce 产物，26 场景）跑两档位：

| 档位 | 场景 26 → 输出 | MERGE | DROP | CONDENSE 标记 | 实际比率 vs 目标 |
|---|---|---|---|---|---|
| light | 23 | 3 | 0 | 0 | 0.885 vs 0.7 |
| standard | 23 | 3 | 0 | 0 | 0.885 vs 0.5 |

**两个校准点（供人工评审裁量）**：

1. **保护集粒度过粗**：保护章 = 死亡/揭示/open threads 起止 → 本样本 13 章里 9 章被保护，且"major 出场"几乎命中全部场景 → v1 规则下没有任何场景可 DROP。校准方向：
   保护应从"章"细化到**场景内事件**（死亡/揭示发生的那个场景），open thread 的保护应只覆盖"提出/回收的具体场景"而非整章；
2. **`isMajor` 缺省过宽**：卡中未显式标记时按"主要"处理（`isMajor !== false`），进一步压缩了可删空间。校准方向：卡产出应显式标注比例，或 POC 增加"仅显式 isMajor=true 才保护"的对照档。

**结论**：v1 判据按设计是保守的（宁可不删）——首跑数据把"保守到什么程度"量化出来了；档位比率（0.7/0.5/0.3）与上述两个校准点一并进入人工评审，评审后再回写第四节。

## 九、后果与风险

- 默认 off，主链零变化；开启档位是用户显式行为。
- 判据是启发式——"支线"识别可能误伤（如反派独场但推动主线）；由决策表 + 人工评审兜底，**不做自动裁决**。
- 忠实度叙事更新：从"不压缩"改为"**可选压缩 + 损失双向可测 + 决策可回溯**"——这是把取舍显式化，而非放弃忠实度。
- 真实编剧对判据的认可度未知 → 纳入 FIX-16 从业者访谈问题集（"你会怎么排序这些场景的取舍？"）。
