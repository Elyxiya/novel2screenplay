## 2. T1 任务（Trae 执行）

目标：把工作区 93 项改动收成**四个主题提交**，每个提交都能单独回滚，且仓库回到"任意提交绿灯"。

### T1-1 按主题拆分提交

| 提交 | 建议范围 | 预期文件数 |
|---|---|---|
| C1 `feat(ui): 深色电影工作台主题落地` | `globals.css`、`layout.tsx`、`app/*/page.tsx`、`components/**`、`ThemeSwitcher.tsx` | ~30 |
| C2 `refactor(test): 测试迁移至 src/__tests__` | `apps/screenplay/__tests__/**`（10 删除）与 `src/__tests__/**` 的新/改文件 | ~13 |
| C3 `refactor(lib): 仓储与多智能体模块整理` | `src/lib/**`（含 `llm/adapter`、`multi-agent`、`store/sqlite`） | ~19 |
| C4 `docs: 项目材料与文档更新` | `docs/**`（含 \`项目框架.md\`、答辩 pptx 两份，均 <100KB） | ~13 |

**硬性要求**

1. 每个提交必须独立通过 `npm run lint`、`npm run typecheck`、`npm run test`（可以只在最后统一跑一次全量，但**必须**在收口报告里给出全量输出）。
2. 不得为了"分组好看"把单个文件的改动拆到两个提交。
3. 提交信息用 Conventional Commits，描述意图而不是 diff。
4. **不得夹带**：`scripts/eval/samples/**`（金标注）、`scripts/eval/baseline.mjs` 的 RUNS、`docs/conversion-quality/` 三份核心文档（账本 / flip / 快照）除非本任务明确要求。

### T1-2 测试迁移对账

C2 涉及"删旧测试 + 加新测试"，必须给出：

- 迁移前后用例数对比（当前基线 **747**，主包 86 文件）；
- 若总数减少，逐条列出"删掉的用例 → 替代覆盖在哪"，无替代的一律恢复；
- 若总数增加，说明新增覆盖了什么。

### T1-3 遗留项清单

收口后仍留在工作区的内容，逐条说明**为什么留**（例：属于下一批 P1、属于别人未完成的工作、需要 owner 决策）。不允许出现"没注意"的遗留。

### T1-4 收口报告（回报格式，固定）

```
## 提交
C1 <hash> <subject> ｜ <n> files
C2 ...
## 验证
npm run lint      → <exit code>
npm run typecheck → <exit code>
npm run test      → <pass/fail 数>
git status        → <剩余项数 + 逐条原因>
## 偏离
<与本文档不一致之处，无则写"无">
```

## 3. 验收口径（reviewer 逐条核对）

- [ ] 四个提交的 `git show --stat` 与 §T1-1 声明范围一致，无越界文件
- [ ] 每个提交不含 `samples/`、不含 `baseline.mjs` 的基线数值改动
- [ ] lint / typecheck / test 三条命令的**实际输出**已贴出（不是"通过了"）
- [ ] 测试用例数 ≥ 747，或有逐条例外的替代说明
- [ ] `git status` 剩余项均有归属说明
- [ ] 提交信息合规、单提交单一主题
- [ ] 没有推送 `main`
