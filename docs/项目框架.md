# Novel2Screenplay 项目框架

> 版本：v0.2.0 | 整理时间：2026-08-28 | 当前阶段：P1 完成 + 架构基座收敛 + PG 多后端落地（R6 待 PG 环境）

## 项目定位

Novel2Screenplay 是基于 AI 的小说转剧本工具：用大语言模型把叙事小说转换为结构化 YAML 剧本，并进一步拆分为短剧分镜，提供可视化的编辑、评测与导出能力。项目从 2026-06-05 启动，单人开发，当前已从单应用演进为 monorepo。

## 技术栈

| 类别 | 技术 |
|------|------|
| 框架 | Next.js 16（App Router，dev/build 均用 webpack） |
| 语言 | TypeScript 5 |
| UI | React 19 + Tailwind CSS 4 |
| 数据库 | SQLite（better-sqlite3）主用；PostgreSQL 可选（`DATABASE_URL` 探择，DB 级隔离测试） |
| AI 集成 | 自定义 LLM 抽象层（DeepSeek 主 / OpenAI 备 / 自定义 OpenAI 兼容与 Anthropic，含用户级 LLM 导入） |
| 序列化 | YAML + Zod 4 校验（tiktoken 费用估算） |
| 测试 | Vitest + Testing Library + MSW |
| 工程 | npm workspaces monorepo + GitHub Actions CI + Docker |

## 核心业务流

1. 小说 → 剧本：上传解析 → 四阶段流水线（分析角色地点 → 场景切割 → 并行场景转换 → 合并去重校验）→ 剧本 YAML → 可视化编辑 → 导出（YAML/JSON/Excel）
2. 剧本 → 短剧分镜：`dramatize` 引擎按规则拆分为分镜，支持编辑 / 删除 / 统计面板 / 导出
3. 创作模块：创作台草稿 CRUD → AI 续写 / 扩写 / 改写 / 润色 → 物化转剧本

## 关键机制

- **流水线健壮性**：信号量 3 并发 + Token Bucket 限流（50 req/min）+ 3 次重试 + 降级输出（`degradedScene`）、任务恢复（从 Phase 3 重跑失败场景）
- **上下文裁剪（Token 优化）**：Phase3 按 `keyCharacterNames` / `sourceChapterIndex` 过滤角色地点上下文，tiktoken 编码器单例化，convert-scene Prompt 精简约 50%
- **LLM 输出处理**：safe-json 四层降级解析 + 截断检测 + 防幻觉 Prompt（只写可见可听动作、对白必须源于原文）
- **存储**：双后端存储抽象（`@novel/db` DbEngine 同步抽象：SQLite better-sqlite3 / PostgreSQL pg+Atomics 桥）。job / novel / drama / history / project / user / writer-novel / agent-task / user-llm 多表，按 userId 数据隔离（越权 403）；repository 与 schema 双后端语义对齐（参数化契约测试）；`user_llm.api_key` AES-256-GCM 加密存储（`enc:v1:`，旧明文启动自愈迁移）
- **实时推送**：SSE（init/progress/phase/log/complete/error/heartbeat 事件）+ 心跳 + 自动重连 + 轮询降级
- **Agent 化**：AgentCore 状态机 + 三级记忆 + 工具调用循环；多 Agent 编排（supervisor/writer/editor/analyzer/validator）+ 交接协议 + 质量关卡；调试日志全量记录 LLM 对话与工具调用
- **外科式 supervisor（conversion-quality Task 4，默认关）**：ReviewGate 增 `identity` 信号（确定性身份断言规则优先）→ orchestrator 决策层对身份不一致场景发 **re-convert 请求（只决策不执行）**，escalation 预算 K=3 超限升级 `manual_review` → 经典链重转桥接器（jobId 取 pipelineState → Phase3 组装器 + Phase3SceneConverter 单场景重转 → 写回 → 重跑身份断言）→ supervisor 经 registry/handoff 产出人工介入证据链；`enableIdentityReconvert` 默认 false，主链零变化
- **Phase1 翻默认（conversion-quality Task 5）**：翻默认唯一触发器是数据门槛——决策规则出数前固化在 `eval/flip-decision`（R1 缺稳定性方差不裁决 / R2 Δ_tail 须大于 judge 噪声带 / R3 尾段差 ≥ Δ_tail 且总分不劣才翻），Δ_tail 由 stability 报告 `deltaTailThreshold` 注入；`pipeline/phase1-budget` 守卫已把 `canRequest`（BudgetController）接到 Phase1 map/reduce/truncate 三个调用点（超限优雅降级 + 记 `metadata.budgetBlocked`），默认模式收敛为 `resolveDefaultPhase1Mode()` 单一决策点——翻默认=改为返回 `mapreduce`（数据门槛未过前保持 `truncate`）
- **Agent 任务持久化（P-记忆）**：orchestrator 任务全量 JSON 落库（`agent_tasks` 表），重启恢复——awaiting 保持挂起、running 置回 pending 自动续跑；已并入双后端测试覆盖
- **对话式中途追问（FR-7）**：质量关卡 awaiting 挂起时支持自由文本建议（`revise` 人工介入动作），累积进 `task.instruction` 供后续阶段沿用，结果页支持局部场景追问修订
- **效果评测**：FlowEvaluator 纯函数评测（format/consistency/coherence/drama 加权 + Token 效率）+ LLM 四维质量评估（`eval/llm-quality`，落库 + SSE quality 事件）+ 8 样本质量基准集（`/api/debug/quality-benchmark`），`/debug` 页面可视化
- **conversion-quality 文档（JD 叙事 / 决策记录）**：同构类比表见 `docs/conversion-quality/jd-analogy.md`（小说→剧本 ↔ 代码工程）；JD 1–6 覆盖与诚实空档标注见 `jd-coverage.md`；Phase1 翻默认决策写实（含待 1b 补齐的分层曲线）见 `flip-decision-record.md`
- **自定义 LLM**：CustomOpenAIProvider（OpenAI 兼容，含 Ollama 本地）/ CustomAnthropicProvider（原生 Messages API）；用户级 LLM 导入（`/api/llm` 增删改 + 连通性测试）
- **认证**：会话 Cookie 认证（应用内 `lib/auth`：password / session / store），RequireAuth 覆盖业务页；历史记录已由 localStorage 收敛至 SQLite（`/api/jobs/history`）

### PostgreSQL 后端（可选）

- **启用**：配置 `DATABASE_URL=postgres://user:pass@host:5432/dbname` 后，启动时 `getEngine()` 按环境探择：PG 健康检查通过 → 启用 PG 并自动建表（schema-pg），否则优雅回退 SQLite。
- **同步语义**：`@novel/db` 提供 DbEngine 同步抽象（prepare.run/get/all），PG 侧经独立 worker 线程 + SharedArrayBuffer + Atomics 同步桥（`STORAGE_SYNC_MODE=bridge`）实现；repository 代码零改动。
- **数据迁移**：`node packages/db/scripts/migrate-sqlite-to-pg.mjs <sqlite.db> [--backup] [--truncate] [--dry-run]`（旁路脚本，不入库；先 `--backup`）。按外键顺序搬移 9 张业务表，迁移后双向校验（行数 + 抽样全列比对）。
- **双后端测试**：契约测试（`repository-contract.test.ts` / `schema-parity.test.ts`）参数化双跑——有 `DATABASE_URL` 追加跑 PG（连接自动解析到 `_test` 后缀库，DB 级隔离），否则仅跑 SQLite。

## 已知限制与演进方向

- **PG 实跑待环境**：双后端契约/迁移脚本已就绪，但真实 PG 联跑（R6）需配置 `DATABASE_URL` 后验证（契约测试、迁移脚本全量模式、e2e on PG）
