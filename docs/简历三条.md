## 三条主条目

**1. 长文本上下文工程（主推）**

> 整本小说几十万字装不进上下文，原方案按比例截断到 3 万 token，截断点落在句中，样本里 59% 的正文从未参与实体分析，后段角色整批丢失。实现三条路径——按章并行抽取后归并成全局设定卡（每个实体记录称呼出处）、整本不截断送长上下文模型、以及原截断基线——切换收敛到单一决策函数，配 token 预算守卫，超限降级而非中断；Phase3 的场景上下文改为「主角卡常驻 + 配角按本章在场名单注入 + 前 5 章滚动摘要 + 未闭合伏笔按章节区间注入」，prompt 体积与全书角色数解耦。
>
> 结果（reviewed 金标注，3 样本 × 3 次）：Phase1 F1 均值 0.752 → 0.886；截断最狠的样本角色召回 10.7 → 34（金标 27）；溯源率 3.97% → 96.9%。默认值按"超过 3 万 token 走归并、否则截断"分流，回滚只需一个环境变量。
>
> 边界：3 个样本、均值±σ 而非单次；归并路径输入 token 约为截断的 1.5–2.5 倍。

**2. 任务可靠性与可观测**

> 任务状态原先在内存里、靠模块级全局变量躲热重载，重启即丢、多实例不共享。改为落 SQLite，同时保留原类与方法签名做兼容壳，几十个调用点零改动；恢复锁从进程内 `Set` 换成数据库单条 `UPDATE` 的 CAS（锁为空或已过期才可抢，以 `changes > 0` 判定），配 10 分钟 TTL 与 TTL/3 心跳续锁，进程崩溃后锁自行过期；恢复逻辑从"重跑全量"改为只重跑失败与待处理场景，再按场景号与旧产物对齐重合并。
>
> 同时把"不可信"变成可查询数据：9 个错误码结构化落库、运行期指标（token / 预算拦截 / 占位率 / 阶段耗时）持久化并提供聚合端点、四阶段写入运行事件与阶段产物快照，支持按时间线回放与单场景重跑对比；取消从"只重置状态"改为贯穿执行链。
>
> 边界：这是单库 CAS，不是分布式锁；`jobStore.update` 仍无版本号并发保护，3 个并发场景写同一数组理论上会丢写。

**3. 质量评测与数据化决策（差异化）**

> LLM 输出质量靠"看着还行"无法迭代，且早期评测把自己那次运行当金标注，F1 恒为 1.0。建立完整链路：预标注 → 人工抽检 → 冻结金标注 → 打分；每样本 3 次运行出 mean±σ，区分「跨运行一致性」与「准确率」并剔除自证运行；Phase1 三模式 A/B、judge 复跑方差、提示词版本对比、模型×样本矩阵、逻辑漏洞检测全部脚本化，状态快照一键生成、不手抄数字。
>
> 翻默认这类决策先冻结判据（缺数据不裁决、尾段差须大于 judge 噪声带），最终翻默认作为「所有者决策覆盖预注册门槛」显式记录，附风险与回滚；文档与代码的一致性由 12 类检查脚本兜底（当前 12/12 通过），单测 747 例全绿。
>
> 边界：judge 尚未人工校准（σ 达 13）；样本仅 3 本且全部是训练集，无 holdout，只能支撑方向性结论。

## 备选条目（偏 LLM 工程 / 偏后端时替换第 3 条）

> LLM 结构化输出的容错解析：模型返回常带 Markdown 围栏、尾随逗号、单引号键名，且长输出会被截断；解析失败时返回的哨兵对象一旦被调用方漏检，重试就永不触发，长篇会静默丢光角色卡。实现四层降级解析 + 括号配对提取 + 截断判定，在调用点拦截哨兵主动抛错让重试生效；3 次仍失败则输出带 9 类错误码与 `confidence 0.1` 的降级场景，失败留在产物里可筛出，而不是整条任务失败。
